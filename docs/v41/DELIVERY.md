# SpecWATT Experience V4.1 Candidate

Приёмка продолжена 11 ноября 2026 года. Браузерные изображения сохраняют явно указанную тестовую дату 10 ноября; Android-снимки используют системное время эмулятора.

Рабочий результат: 12 маршрутов, три шага Setup и 15 состояний в React и редактируемой Figma; соответствующие нативные экраны React Native. [Полная визуальная приёмка](review.html) содержит V4 → V4.1 и 29 независимых React ↔ Figma пар. Локальное интерактивное приложение: http://127.0.0.1:4174/#home.

## PASS 2 — редактируемая Figma

Через отдельный авторизованный `figma-remote` проверены файл, реальные типы узлов, свойства и сохранённый результат. Новые страницы содержат Auto Layout, TEXT, VECTOR, image fills, настоящие INSTANCE и COMPONENT; сплошных скриншотов интерфейса нет. Фотографии занимают только предметные и интерьерные области. Все текстовые диапазоны используют Manrope.

Сохранены исходные 62 переменные (31 primitive + 31 semantic), семь text styles и исходная библиотека V4. Новые устройства и энергобаланс переиспользуют эти переменные. Toggle имеет четыре варианта, On/Off — переход 160 мс. 29 prototype frames имеют 210 назначенных переходов. [Прямой аудит](figma-audit.json) содержит актуальные counts и размеры.

Исправлены: сброс alpha после привязки к непрозрачному alias, размеры строк после замены master, крупный нативный range input, неизвестные значения в бюджете, затемнение Lighting Off, положение листов Planner, check вместо стрелки при сохранении, регистр заголовков Settings и прозрачность нижнего логотипа. Временные DOM captures и устаревшие candidate masters удалены. Исходная обложка снова содержит только `29:231`, исходный Home `15:386` сохранил высоту 1109,6875 px.

Playback инструменты не предоставляют. Назначение переходов и цели прочитаны из файла; реальное воспроизведение Figma не заявляется проверенным. Code Connect не публиковался — передана явная карта исходников и узлов.

## PASS 3 — визуальное и поведенческое соответствие

29 React PNG и 29 Figma PNG получены независимо, при 393 px, совпадающих состояниях и тестовом времени 18:54. Все пары просмотрены; исправления проверены новыми Figma-снимками. Варианты day/month, saved/editing/conflict, consent, loading/error/offline, CH1 on и CH2 off входят в сравнение. Неизвестная текущая мощность обозначена «—», не нулём.

Остаются особенности разных рендереров: сглаживание текста, локальные тени, градиенты, положение мелких SVG-подписей и несколько пикселей высоты листа Planner. Android использует собственные Switch, системную клавиатуру, статус/навигационную панель и прокрутку; точное пиксельное совпадение с вебом не заявляется. Нативный журнал начинает с одного системного события, веб — с двух; оба показывают только реальные события своей демо-сессии.

18 unit tests прошли: CH1 1,8 Вт, CH2 4,2 Вт, CH3 2,4 Вт, предел 7 Вт, отказ 8,4 Вт без изменения состояния, неизвестное соединение, разрешения, валидация и конфликт расписаний, точные энергетические интервалы и новый ввод времени с цифровой клавиатуры.

Отдельная V4.1 регрессия проверяет остановку расчёта автопилота при 8,4 Вт и отсутствие изменения каналов. [Основной отчёт](qa-browser.json), [регрессии](qa-regressions.json), [движение и состояния](qa-motion-states.json), [V4.1](qa-v41.json).

Сама защитная модель `src/model.ts` не изменена. CH3 не включён ни в переключатели, ни в планировщик, ни в управление автопилотом. Расписания не исполняются по времени, аппаратное диммирование и телеметрия не имитируются.

## PASS 5 — сборка и передача

Пройдены unit tests, TypeScript web/native/host, Prettier, production Vite build и Expo Hermes (774 modules, 5 bundled assets, 1,9 МБ HBC). Production preview отдельно проверен на загрузку Manrope, исправления V4.1 и axe. На всех 12 маршрутах axe не сообщил нарушений проверяемых правил WCAG A/AA; это автоматический аудит, не сертификат полной доступности. [Результат](accessibility.json).

Android APK реально собран, установлен и запущен на `specwatt_v6_test` x86_64. Gradle `BUILD SUCCESSFUL`; [лог](android/build.txt). В APK встроены JS, Manrope и четыре фотографии. Найден и исправлен повторный выпуск старого JS: файлы общих экранов вне Expo host теперь включены в inputs задачи сборки. Отдельный Expo config plugin отключает поиск Metro только для embedded preview, устраняя белый экран после остановки среды разработки. Реальные кадры выявили и помогли исправить crop спальни, повторный верхний блок, высоту инвентарных строк, карточный фон Autopilot, перенос недели Planner и подписи навигации при fontScale 1,5.

42 настоящих Android-снимка охватывают 12 маршрутов и три шага настройки при fontScale 1,0 / 1,3 / 1,5. Исходный масштаб восстановлен. [Протокол снимков](android/capture-results.json). Через реальные касания прошли пять проверок: отказ 8,4 Вт с CH1 off, запись отказа и аппаратный Back, unknown/disabled offline, цифровой ввод `2359 → 23:59` с сохранением черновика после закрытия клавиатуры, Setup Back 3 → 2. [Результаты](android/interactions/results.json), [перегрузка](android/interactions/overload-refused.png), [клавиатура](android/interactions/planner-keyboard.png), [offline](android/interactions/offline-home.png). На реальном снимке исправлены буквенная клавиатура Android и пересечение заголовка редактора со статус-баром: используются numeric inputMode, Safe Area и спокойная кнопка закрытия. IME input class проверен через Android. Текст уведомления включён в доступное имя и live region; вывод TalkBack вслух отдельно не проверялся.

При холодном старте `uiautomator` однажды вернул `null root node`. Снимки теперь ждут реальный заголовок нужного маршрута, с ограничением в три проверки готовности; старый XML не используется. Проверки бизнес-сценариев не повторяются автоматически после неуспешного assertion.
