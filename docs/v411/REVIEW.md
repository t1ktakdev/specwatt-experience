# SpecWATT V4.1.1 — результаты исправлений

Работа продолжает PR №3 (`183fe52a226ef7870aeccb08c8772cccf24579e3`) в отдельной ветке `codex/experience-v411-review-fixes`, PR №4. Основной SpecWATT и ветки PR №2/№3 не изменялись. Публикация сайта не выполнялась.

Это передача исправлений на повторную визуальную приёмку, а не объявление всех пунктов PASS. **Остаётся ограничение системных значков эмулятора Android 15/API 35:** фон панели теперь тёмный, корректный запрос светлых значков и edge-to-edge проверены, но этот образ продолжает рисовать значки тёмными. Исправление их фактической окраски не заявляется. Физический Android не проверялся. Ограничение описано в [Expo NavigationBar](https://docs.expo.dev/versions/v58.0.0/sdk/navigation-bar/) и [первичном отчёте Android](https://issuetracker.google.com/issues/346386744).

[Сравнить реальные изображения в локальной галерее](review.html). [Home до/после](review/home-1.0-before-after.png), [Home при 1.5](review/home-1.5-before-after.png), [Planner — деталь кнопки](review/planner-button-detail.png). Изображения приложения не ретушировались: сравнительные листы только располагают и масштабируют реальные кадры.

## Planner в Figma

Исправлены существующие `75:2002` и его копия в Prototype `91:1359`, а не создан новый макет. Обёртка `75:2139` имела ширину 100 px при дочерней кнопке 305 px; центрирование давало x = −102.5 px. Теперь обёртка занимает две колонки Grid, имеет ширину 305 px, кнопка заполняет её через FILL. Ручного отрицательного смещения нет.

## Prototype — реальные переходы и playback

Проверены 29 существующих фреймов и 241 назначенное действие: отсутствующих целей и несовместимых типов не найдено. Добавлены пропущенные переходы строк Settings/Device/Energy, возвраты Setup и закрытие редактора. CH1 в исходном состоянии ведёт к отказу 8.4 Вт; «Понятно» возвращает на исходный экран через BACK.

Playback выявил дефект, невидимый при простом аудите связей: абсолютное положение Nav не делало её закреплённой. Исправлено `numberOfFixedChildren` для StatusBar/Nav, включая порядок слоёв редактора. Новые переходы сбрасывают прокрутку цели. [Кадр после реальной прокрутки Planner](figma/playback-planner-fixed-nav.png) показывает закреплённую навигацию и кнопку внутри карточки.

В браузере реально пройдены Welcome → Home → Devices → Device → отказ → Device → Back; Autopilot → прокрутка → Planner → первое расписание → редактор → сохранённый пример; Settings → Setup 1/2/3 → Home и 3 → 2; Energy День/Месяц/Неделя. Цели подтверждались изменением node-id и снимками. [Аудит](figma/prototype-audit.json).

Figma остаётся демонстрацией кадров: свободный ввод и условные вычисления разрешений не выдаются за работающий симулятор. Реальные редактирование, разрешения и защита проверяются в React и установленном Android.

Итоговая проверка PR также доступна на его вкладке Checks.

Новая отдельная Android-сборка: `dev.specwatt.experience.v411.preview`, x86_64, встроенный JS без ожидания Metro. Установлена на Android 15/API 35, 1080×2340, 440 dpi. [Метаданные и SHA-256](android/build.json). Чистый Expo prebuild воспроизводит Kotlin activity из конфигурационного плагина; код не держится на ручной правке сгенерированного проекта.

Полная визуальная серия содержит 42 состояния × top/bottom = 84 PNG и XML. После последней локальной правки ползунка повторены именно Lighting при всех трёх scale и сквозные нажатия; [происхождение каждого кадра](android/capture-results.json) хранит SHA-256 APK. [Проверки нажатий](android/interactions/results.json), [жест ползунка](android/interactions/slider-results.json). CH1 1.8 Вт, CH2 4.2 Вт, защищённый CH3 2.4 Вт, предел 7 Вт и отказ 8.4 Вт сохранены. Общая модель, её разрешения и runtime не переписывались. Оборудование не подключалось, телеметрия и подтверждения команд не создавались.
